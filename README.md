# 北美市场AI情报助手 (NA Market Intel Copilot)

> 一句话定位：输入竞品品牌，自动汇总广告素材与用户评论，生成周度市场洞察与可执行GTM建议。

![demo](sample_outputs/demo.gif)  <!-- 第3周替换为录屏动图 -->

## 问题 (Problem)

在跨境电商北美市场做选品与投放时，竞品监控主要靠人工：翻评论、截图广告、记价格。
问题有三：**慢**（一个品类盯3个竞品，每周至少4-5小时）、**主观**（不同的人读出不同的结论）、**不闭环**（洞察看完就忘，没有沉淀为可执行动作）。

## 方案 (Solution)

四阶段LLM管道，把"原始素材 → 周报 → GTM动作"流程化：

```
原始素材            阶段1            阶段2           阶段3          阶段4
评论/广告/价格 ──> 素材提取器 ──> 品牌周度汇总 ──> 竞品对比矩阵 ──> GTM建议
(手工CSV)        (逐条结构化)   (主题/情绪/需求)  (价格带/差异缺口) (机会+动作+风险)
```

- LLM：DeepSeek (`deepseek-chat`)，JSON输出模式保证下游可解析
- 前端：Streamlit
- 数据：手工维护CSV（`data/`），可扩展为定时API抓取

## 关键设计决策 (Key Design Decisions)

1. **为什么拆成四阶段，而不是一个长prompt？**
   - 可控性：每阶段输出固定JSON schema，坏了一环只需重跑一环，且能逐环节检查质量
   - 成本：阶段1逐条调用但只花几百token；若整包塞给一个prompt，重复上下文会显著增加成本
   - 温度分层：提取(0.2)→汇总(0.3)→对比(0.4)→创意建议(0.5)，越靠后创造性越高
2. **为什么先用手工数据而不是先写爬虫？**
   先用小样本验证prompt质量和报告可用性（1周），确认价值后再自动化采集——先验证流程，再投入工程。
3. **为什么把"GTM建议"单独成阶段？**
   洞察不值钱，动作才值钱。单独一个prompt并明确要求"谁、做什么、在哪个渠道"，是为了对抗LLM输出正确废话的倾向。

## 局限性与下一步 (Limitations & Next Steps)

- 样本量小（每品牌10余条），结论仅供演示；下一步接Amazon PA-API / 广告透明度中心API定时采集
- LLM可能放大个别评论的情绪权重，考虑引入基于规则的情绪基线做交叉校验
- 建议的"可执行性"依赖我方定位输入的质量，考虑加入历史投放数据做反馈闭环

## 本地运行 (Run Locally)

```bash
pip install -r requirements.txt
cp .env.example .env   # 填入 DEEPSEEK_API_KEY
streamlit run app.py
```
